# test-ransoware

> **⚠️ Dangerous software — do not run on a personal, work, or otherwise valuable computer.** This repository contains ransomware-like code that can overwrite and rename files across Windows drives. Use it only for static analysis or, if absolutely necessary, in a disposable, isolated virtual machine with no shared folders, network access, or valuable data.

## English

### Overview

This repository is an educational ransomware simulation written in Python. The script `ransoware.py` generates an AES-256 key, encrypts it with an RSA-2048 public key, searches Windows drives from `C:\` onward for files with selected extensions, overwrites and renames matching files with the `.encrypted` suffix, and attempts to place a ransom note on the desktop.

The script also writes key material, including the RSA private key, to `backup_keys.json`. Treat that file as sensitive. The implementation is destructive and does not include a recovery utility; encryption uses AES-CTR without authentication. Do not assume encrypted files can be safely or reliably restored.

### Safety

- **Do not execute this script on a host containing data you care about.**
- For analysis, prefer reading the source without running it.
- If execution is essential for a controlled lesson, use a disposable VM snapshot with networking and host integrations disabled. Use only synthetic test files and revert the snapshot afterward.
- Never deploy this code, run it on third-party systems, or use it to encrypt someone else's data.

### Repository contents

- `ransoware.py` — the ransomware simulation.
- `prérequie.txt` — lists the PyCryptodome dependency.
- `backup_keys.json` — key material generated by a run; do not publish real generated keys.
- `LICENSE` — MIT License.

## Français

### Présentation

Ce dépôt contient une simulation pédagogique de rançongiciel écrite en Python. Le script `ransoware.py` génère une clé AES-256, la chiffre avec une clé publique RSA-2048, recherche des fichiers correspondant à certaines extensions sur les lecteurs Windows à partir de `C:\`, écrase les fichiers trouvés et les renomme avec le suffixe `.encrypted`. Il tente aussi de déposer une note de rançon sur le bureau.

Le script enregistre également des éléments de clé, dont la clé privée RSA, dans `backup_keys.json`. Considérez ce fichier comme sensible. Le programme est destructeur et ne fournit pas d’outil de récupération ; le chiffrement AES-CTR n’assure pas l’authenticité des données. Ne partez pas du principe que les fichiers chiffrés pourront être restaurés correctement ou sans risque.

### Sécurité

- **N’exécutez pas ce script sur un ordinateur contenant des données importantes.**
- Pour l’analyse, privilégiez la lecture du code sans l’exécuter.
- Si une exécution est indispensable dans le cadre d’un exercice contrôlé, utilisez une machine virtuelle jetable avec instantané, sans réseau ni intégration avec l’hôte. Utilisez uniquement des fichiers de test synthétiques, puis restaurez l’instantané.
- Ne déployez jamais ce code, ne l’exécutez pas sur des systèmes tiers et ne l’utilisez pas pour chiffrer les données d’autrui.
